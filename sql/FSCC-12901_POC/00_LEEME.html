POC: flujo completo con datos reales

Prueba desde SQL de T1 (DI automática) → T2 (cierre automático de cierres Y), sin pasar por el exe, con cajas reales copiadas de test y con los 486 sobres reales de PRD 3.

AmbientesInicio rápidoFlujoDatos de test Día PRD 3PasosQué mirarDeshacerCuidados

Ambientes

Test

  • Tiene datos reales: cajas de 2026.
  • No permite crear objetos.
  • En la POC solo se lee, con 02g_generar_datos_test.sql.

Desarrollo (INTRANETDE)

  • Permite crear objetos y tiene instalados los 8 objetos de FSCC-12901.
  • Casi no tiene datos de FACO (hasta 2022).
  • Aquí se carga y se ejecuta todo.
Los dos esquemas están en la misma base, pero desarrollo no puede leer las tablas de test. Por eso los datos pasan como un script de INSERTs (02_datos_test.sql), ya generado. Las claves no se guardan en estos archivos.

Inicio rápido

  1. Conéctate a desarrollo en DBeaver y activa la salida del servidor (Ctrl+Shift+O).
  2. Ejecuta como script (Alt+X), en orden: 01 → 02 → 03 → 04 → 05 → 06 → 07.
  3. En 07 revisa que la columna diferentes = 0 en todos los escenarios.
  4. Para repetir: 98_reiniciar.sql → 06 → 07. Para dejar el ambiente limpio: 99_limpiar.sql.

A. Cajas reales de test

Son 714 cierres Y de 2026 (446 abiertos) en 55 local-día, sobre todo del 07-01-2026. Se copian con su libro de ventas, el detalle zzz y las tarjetas reales. En test no tienen sobres, así que la POC los genera simulando Form133:

E1, E2 y E3 solo se asignan a cajas sin DI previa y sin reglas que las bloqueen; si una caja no califica, pasa a R0.

B. Día PRD 3 (28-08-2026)

Se cargan los 486 sobres reales de PRD 3.xlsx (357 cajas, 27 locales, $992.569.000). En test no hay cajas de ese día, así que se crean los cierres Y y el libro de ventas usando como molde una fila real de test. El efectivo declarado se calcula para que la DR quede en el valor del escenario:
