Magnitud global: media-alta. 4. Validaciones de "Cerrar Terminal" a replicar

Fuente: Form3Y.CierraTerminal (Form3Y.frm:2801) para la Y y Form3.CierraTerminal (Form3.frm:3439) para la Z. SQL completo de cada una en docs/CierreCaja_FACO_Reglas.md §3–§6. Se evalúan en orden; la primera que falla bloquea y su mensaje va al log.

Diferencias con el diagrama del proceso 2. El diagrama resume las validaciones como "conceptos por regularizar, tarjetas, monto por compensar, suma Y = Z, Y abiertos". En el sistema real, para Colombia: tarjetas no aplica (solo ARG/SOAR/SOUY/CHI/CMCL); faltan cheque a fecha (RY-01/RZ-01), estado Impreso o Sin datos (RY-02), ZZZ (opción 103) y dólares (opción 109); "suma Y = Z" e "Y abiertos" son validaciones de la Z (RZ-06, RZ-07), no de la Y. El diseño de este documento usa la lista real.

El diagrama cierra la Z apenas se cierra la última Y ("¿Cierre Y y todas las Y cerradas? Sí → Cerrar el terminal-día (Z)"). En el sistema la Z tiene validaciones propias (RZ-05, RZ-06, RZ-09) que pueden fallar aunque todas las Y estén en 0. El diseño ejecuta las RZ antes de cerrar la Z; si fallan, la Z queda Pendiente con motivo (N5).

4.3 Validaciones que dependen del perfil (P5)

Un proceso automático no tiene perfil. Opciones: (a) evaluar con el perfil del analista que ejecutó la carga (PERFILUSER, consultando vta_FACOrelpermen); (b) definir un perfil fijo de proceso. Consulta de permiso:

select 1 from vta_FACOrelpermen p, vta_FACOmenu m
 where p.mnu_codigo = m.mnu_codigo and p.per_codigo = :perfil
   and p.mnu_codigo = :opcion and p.rel_estado < 0;     -- 103 ZZZ, 109 dólares

5.2 Universo

  • Y: las cajas de la carga (mismo universo de T1) en estado −1/0, incluidas las de DR 0 que T1 no tocó (T2: "incluidas las ya cuadradas").
  • Z: los terminal-día de esas Y. Nunca recorrer todas las Z pendientes: hay ~2.180 precreadas por día en −1.
  • Excluir con motivo: Y sin libro de ventas (SIN_LIBVTA), Y cerradas que recibieron sobres (P12, Y_CERRADA_CON_DIF).

7. Algoritmo

si parámetro DIA_T2 <> 'S' -> log T2_INACTIVA ; terminar
-- Fase Y
para cada Y del universo (orden fecha, local, terminal, cierrey):
    savepoint y
    select ter_estado from vta_FACOtermstaty ... for update nowait   (si bloqueada -> log OCUPADA)
    si ter_estado > 0                         -> log RY-02 ; continuar
    si no hay libvta Y                        -> log SIN_LIBVTA ; continuar
    regla := FN_F8_FACO_VALIDA_Y(...)         -- RY-01, RY-03, RY-05, (RY-06 según perfil)
    si regla <> OK                            -> log NO_CERRADA (regla, mensaje) ; continuar
    update termstaty -> estado 1, cerradopor
    commit ; log CERRADA_Y

-- Fase Z
para cada terminal-día del universo:
    savepoint z
    select ter_estado from vta_FACOtermstat ... for update nowait
    si alguna Y del terminal-día no está cerrada -> log RZ-07 ; continuar
    regla := FN_F8_FACO_VALIDA_Z(...)         -- RZ-01, 03, 05, 06, (08, 09 según perfil)
    si regla <> OK                            -> log NO_CERRADA ; continuar
    update termstat -> estado 1, cerradopor (+ fechacierre si P4)
    commit ; log CERRADA_Z

10. Riesgos, despliegue y vuelta atrás

Riesgos

  • Romper el cierre AUTOMATICO actual de Autopago si se modifica su paquete sin conocerlo → obtener el cuerpo y cubrir con el caso 14.
  • Divergencia con el cierre manual: hay tres implementaciones en VB6 (Form3, Form3Y, Form43) que no comparten código; la nueva en PL/SQL sería la cuarta. Caso 15 obligatorio.
  • Z = ΣY dinámico: depende de vta_paint_z; un cambio de configuración cambia el resultado.
  • Concurrencia con analistas trabajando en la F8 durante la carga → FOR UPDATE NOWAIT y registro OCUPADA.

Orden de despliegue

  1. (Si P4) alter table de fecha de cierre.
  2. Funciones de validación Y/Z y procedimiento; sinónimos y grants a UINTRANETTS.
  3. Regresión del cierre AUTOMATICO existente (caso 14).
  4. Comparación contra cierre manual (caso 15).
  5. Exe junto con T1; piloto en un local.

Vuelta atrás

-- reabrir lo cerrado por una corrida (si no hubo envío contable)
update vta_FACOtermstaty y set ter_estado = 0, ter_cerradopor = null

                 and l.log_fecha_vta = y.ter_fecha and l.log_local = y.ter_local
                 and l.log_terminal = y.ter_terminal and l.log_cierrey = y.ter_cierrey);

* Según flag. Las cajas con diferencia, bloqueadas, sin libro de ventas, ocupadas o con error quedan en estado P y se reevalúan en la siguiente ejecución (hasta CA_DIAS). Así, si el analista compensa o regulariza, el ciclo siguiente las cierra.

12.3b Integración con T1 (FSCC-12957) y carpeta de instalación

  • PRC_CIERRE_AUTOMATICO es el único punto de entrada: marca omitidas y vencidas en la cola → llama a PKG_F8_FACO_COMPENSA_DI.PRC_COMPENSA_DI (T1, si CA_DI_ACTIVO = S) → cierra Y y Z (T2, si CA_ACTIVO = S). Los interruptores son independientes y un error en T1 no detiene T2.
  • El log distingue cada proceso con log_proceso (T1 / T2 / CC = botón Cerrar Terminal de Form43).
  • Instalación: carpeta consolidada docs/sql/FSCC-12901_T1_T2/ con INSTALAR.sql. El orden es: especificaciones de T2 y T1 → cuerpo de T1 → cuerpo de T2 → trigger.

12.4 Diferencias deliberadas con el exe

  • ZZZ de la Y con la Y real (el exe pasa el local: bug D1).
  • Z sin Y en el libro de ventas: no se cierra (el exe deja pasar, D2).
  • Validaciones de perfil → flags; tarjetas no se valida (no aplica a Colombia).
  • Errores de consulta → caja en ERROR y reintento (el exe a veces dejaba pasar).
